## 3. 小程序自动强制升级 —— 已完成（3 处缺陷已修）

微信原生支持，官方 API 是 `wx.getUpdateManager()`。原来的实现在 `pages/index/index.js` 的 `checkAppUpdate()`，由首页 `onShow` 调用，有三个问题，现已全部修掉，逻辑统一收到 `app.js` 的 `initUpdateManager()`：

- [x] **`onUpdateReady` 注册时机**：原来嵌套在 `onCheckForUpdate` 回调里、且只在 `hasUpdate === true` 时才注册，冷启动时可能错过事件、永远不 `applyUpdate()`。现在三个回调都在 `onLaunch` 里一次性注册（`initUpdateManager()` 在登录之前调用）
- [x] **`onUpdateFailed` 兜底**：原来下载失败静默无提示。现在弹窗告知「新版本下载失败，请检查网络后删除小程序，重新搜索打开」
- [x] **入口覆盖不全**：原来只挂在首页 `onShow`，从分享卡片直达倒班页就不检查。现在挂在 `app.js` 的 `onLaunch`，任何入口都会检查；首页那份重复实现已删除（避免同一事件被重复注册）
- [x] **提示方式**（原「待定」项）：改成 `wx.showModal({ showCancel: false })`，用户点确定后 `applyUpdate()` 重启，比原来一闪而过的 toast 更明确，仍然是强制升级

**遗留待办**：

- [ ] **端到端验证待补**：升级流程要真跑一遍，得先把新版本上传到微信后台。本机微信开发者工具的 CLI 服务端口是关闭状态（设置 → 安全设置 → 服务端口），命令行编译/上传都用不了，所以这次只做了代码级验证，没有在模拟器/真机上跑通「上传 → 检测到新版本 → 弹窗 → 重启」全链路
