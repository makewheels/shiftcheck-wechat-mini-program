## 3. 小程序自动强制升级 —— 已实现，但有 3 处缺陷待修

**结论**：微信原生支持，官方 API 是 `wx.getUpdateManager()`；本仓库**已经写了**，位置 `pages/index/index.js` 的 `checkAppUpdate()`，由首页 `onShow` 调用。当前行为：检测到新版本 → toast「小程序更新，稍后将自动重启...」→ 新版本下载完成后直接 `applyUpdate()` 强制重启到新版（用户无法拒绝，属于"自动强制"）。

**已发现的缺陷（按风险排序）**：

- [ ] **`onUpdateReady` 注册时机有隐患（最要紧）**：现在把 `onUpdateReady` 嵌套在 `onCheckForUpdate` 回调里、且只在 `res.hasUpdate === true` 时才注册。官方推荐在 `onLaunch` 里尽早注册。冷启动时若新版本下载完成得比回调执行更快，`onUpdateReady` 事件已经错过 → 永远不会执行 `applyUpdate()`，用户这一轮就停在旧版。
- [ ] **没有 `onUpdateFailed` 兜底**：新版本下载失败（弱网 / 网络被拦截）时静默无提示，用户长期用旧版且不知情。
- [ ] **入口覆盖不全**：`app.js` 里的 `checkAppUpdate` 是**空函数**，`onLaunch` 也没调用它；真正的检查只挂在首页 `onShow`。若用户从分享卡片等入口直达某个倒班页（不经过首页），这一轮不会检查更新。
- [ ] 是否要把提示从 toast 换成阻塞式 `wx.showModal({ showCancel: false })`，让"必须升级"这件事对用户更明确？—— 待定（现状已是自动重启，功能上够用）

**前置依赖**：升级机制要能真正跑起来，前提是能把新版本**上传并发布**到微信后台。本机微信开发者工具的 CLI 服务端口是关闭状态（工具 → 设置 → 安全设置 → 服务端口），命令行编译/上传都用不了，因此本条**尚未做过端到端验证**。

**备注**：以上均为已读代码得出的结论，未改动任何代码；修的时候注意 `applyUpdate()` 会立即重启小程序，不要放在有未保存输入的页面。
