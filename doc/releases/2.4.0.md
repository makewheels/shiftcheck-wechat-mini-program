## 新功能

- **全部 8 个倒班页新增「月日历」视图**，与原来的一周列表可切换。日历上标出法定节假日（`休`）与调休补班日（`班`），点任意一天回到列表模式并从那天开始显示 7 天。节假日数据内置（来自国务院办公厅通知，已按原文逐条核对 2025、2026 两年；**2027 年通知未发布，故未内置**，日历会提示「该年数据尚未内置」）
- **新增经警队「上一天休三天」排班**（个人 / 总览两个页面）；首页单位名「热电厂」→「中油电能」

## 本版收敛：删掉两条已经死掉的功能链路

注册页面 **20 → 11**，小程序收敛成「纯离线查班工具」：8 个倒班页全部本地计算，只有首页的使用统计上报还连 LeanCloud。

| 删除 | 页面 | 为什么 |
| --- | --- | --- |
| 整条「上班推送」链路 | `pushHome`、`newPushMission`、`updateMail`、`updatePhone`、`accountHome` | 创建任务的入口自 2.2.x 起就被一句裸 `return` 堵死；`PushMission` 表与 7 个推送字段全部只写不读；真正发信的定时任务在已停用的后端仓库里 —— **用户填了真实邮箱手机号也永远收不到** |
| 整条 DIY 自定义规则链路 | `diy`、`diyPush`、`importRuleByKey`、`myRuleHome` | 全仓库没有任何代码能创建 `Rule` / `RuleKey`，**激活码对新用户 100% 报「激活码错误」且无处申请**；导入页还会在登录未完成时烧毁一次性激活码并提示成功 |

顺带消掉的问题：20 秒卡死的 loading toast（15 处全在已删页面里）、`updateMail`/`updatePhone` 的 `users[0]` 未判空崩溃、`accountHome` 的 save 竞态、`pushHome` 三个开关的乐观更新 + 静默失败。

**微信隐私接口归零**（剪贴板随激活码导入页一起删除、邮箱手机号随推送链路删除、从来没有定位）——《用户隐私保护指引》**不再有必须声明的接口项**。`test/hygiene.test.js` 用零容忍门禁守着这个性质。

广告位从 3 个减到 1 个（激励视频与 diy 页 banner 随页面删除），只剩 `adunit-499feca899514736`。

## 修复

| 问题 | 影响 |
| --- | --- |
| 排班基准日**之前**的日期算错班 | 经警队锚点是 2026-09-10，用户往前翻一天就看到错的班次；全部倒班页统一改为有符号天数差 + 负数取模 |
| `scope.userInfo` 授权门禁早已失效 | **「我的DIY规则」和「订阅上班推送」对新用户 100% 走到「授权失败，无法使用」**（这两个入口在本版随链路一起删除） |
| 21 处「登录还没回来就取 openid」 | 首次冷启动手快一点就白屏；已统一收口 + 登录重试 + 页面入口守卫 |
| 「返回主页」深链进入时点了没反应 | 从搜一搜 / 扫码 / 分享卡片直接进倒班页时页面栈只有 1 层，`navigateBack` 静默失败；改为栈深 ≤1 时 `reLaunch` 回首页 |
| 强制升级 3 处缺陷 | `onUpdateReady` 注册时机（冷启动可能错过、永不升级）、下载失败无兜底、非首页入口不检查 |
| 首页「5 分钟内不重复上报」从未生效 | 时间戳存在页面 `data` 里、每个实例都是 0；改用 storage，并补了能抓住这个 bug 的测试 |
| **首页一打开就弹「登录没成功」阻塞弹窗** | 使用统计上报走了「取不到 openid 就补登录、补不上就弹框」的路径，而首页 8 个倒班入口全是本地计算、**根本不需要登录**。网络不通或后端域名失效时每个用户一进来就被拦一下。改成静默跳过，并把那对弹框方法整个删掉、加门禁守着不许复活 |
| 2 处查询结果未判空就取 `[0]` | 新用户点「设置手机」会崩；看完激励视频会显示假的推送次数（两处均在本版随链路删除） |

> 注：本轮过程中还修过「自定义规则提醒」页打不开（页面 json 被误标成自定义组件，v2.3.2 起就有）与 `pushHome` 把位运算 `&` 当逻辑与 `&&` 的笔误 —— 这两个页面随后在同一版里被删除，修复本身留在了 git 历史里。

## 隐私与清理

- **移除首页静默采集**：原来启动后 800ms 会无感读取**剪贴板全文**、请求 ip138 **查 IP 归属**，连同 13 项设备信息写入 LeanCloud。剪贴板与设备信息都属微信隐私接口，未声明会被拦截，后台静默读剪贴板也是监管通报高频项
- 移除废弃 API：`wx.getSystemInfoSync`、`wx.getUserInfo`
- **收紧 sitemap**：只开放首页与 8 个倒班查询页给微信索引（它们纯本地计算、不依赖登录态，被搜到直接能用）
- 删除死代码：`mta_analysis.js`、未使用的 LeanCloud 打包版 SDK（165 KB）、失效的授权页、`feedback` 空占位页、`logs` 模板页、只写不读的 `homepage` 设置

## 工程化（这一版开始有质量门禁）

- **`test/` 测试套件：137 项，`node:test` 零第三方依赖**。用假的 `Page()` / `wx` / `getApp()` 沙箱加载页面 js 直接断言，不启动模拟器。排班算法用五条互相独立的约束钉住：锚点守卫、周期性不变量 `班次(d) === 班次(d+N)`、与真实排班核对过的经警队班表、金标准快照（21 组已校准输出）、列表 == 日历（保证没有第二套班次算法）
- **GitHub Actions 门禁**（Node 24），已设为 `master` 分支保护的必需检查
- 累计注入 **20+ 个变异**验证门禁有效性，全部被抓到 —— 其中两次抓到的是**门禁自身的漏洞**（升级回调嵌套检查看漏了第二处；豁免标记检查把自己要找的行也跳过了）
- **新增单文件行数门禁（上限 500 行）**，排除 `libs/` 第三方 SDK。当前最大业务文件是 `pages/wbsd/worker/worker.js`（352 行），留了约 30% 余量
- **新增门禁：不许恢复「取不到 openid 就弹框挡住用户」那套方法**。守的是**机制**不是文案，换个提示措辞也一样会被拦下
- **发布说明改为以仓库文件为准**：每个版本的 Release 正文存在 `doc/releases/<version>.md`，GitHub Release 用 `gh release edit --notes-file` 从它同步过去（见 `doc/releases/README.md`）
- **测试套件改为跨平台**：原先路径判断用了 `'/libs/'`、`'/pages/'` 这类正斜杠字面量，在 Windows 上一条门禁跑红、另一条（「磁盘上的页面目录都在 app.json 注册」）因为 `dirs` 恒为空而**静默永远绿**。现已统一归一化，本机与 CI 行为一致
- 新增 `AGENTS.md`（仓库须知与陷阱清单）；`doc/changes/` 一次变更一份记录，文件名带时分秒

## 验证与已知边界

- 137 项测试通过（本机 Node v24.15.0，与 CI 同版本）；排班输出与 2.3.4 逐日比对（全部班组 × 1541 天），**锚点及之后 0 处不一致**
- 新增门禁做过反向验证，确认不是「永远绿的死测试」：把行数上限临时压到 300 会准确报出 4 个超标文件；从 `app.json` 摘掉一个页面会让结构门禁立刻变红
- ⚠️ **界面级验证未做**：月日历的格子换行、底色对比度、点击手感，以及 8 个倒班页在窄屏上的排版，需要人工在模拟器或真机上过一遍。上传后请按 [`doc/发布前检查单.md`](https://github.com/makewheels/shiftcheck-wechat-mini-program/blob/v2.4.0/doc/%E5%8F%91%E5%B8%83%E5%89%8D%E6%A3%80%E6%9F%A5%E5%8D%95.md) 第 9 节真机走一遍
- ⚠️ **强制升级全链路未跑通**：「上传 → 检测到新版本 → 弹窗 → 重启」需要真的发一版才能验，代码层的 3 处缺陷已修并有测试守着
- ⚠️ **后端 `api.leancloud.mp.shiftcheck.work` 疑似已失效**：在本机 DNS 解析失败（`getaddrinfo failed`），经代理 CONNECT 也是 `502`。对照测试排除了「本机 DNS 整类封个人域名」——同一台机器上其它个人域名的子域都能正常解析，而这个域名的三级子域全挂。**但本机所在网络按类别封了 DoH 服务，无法从内网确认全球解析状态**，需要用手机流量再验一次。
  影响面：只有首页的使用统计上报依赖它，**8 个倒班页与设置页全是本地计算，查班功能不受任何影响**。统计上报失败现在是静默跳过的（本版修的），用户看不到任何异常。
  若确认已弃用：`libs/` 里的 LeanCloud SDK 占 237.6 KB，是本包 260.9 KB 的 **91%**，删掉可降到 ~25 KB
- 完整逐条变更记录见 [`doc/changes/`](https://github.com/makewheels/shiftcheck-wechat-mini-program/tree/v2.4.0/doc/changes)
