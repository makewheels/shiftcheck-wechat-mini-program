# 2026-09-11 22:35 CI 改回单 Node 版本（24），并同步必需检查的 context 名

## 背景/目的

上一个变更把 CI 做成了 Node **22 + 24 双矩阵**，理由是"`node:test` 的行为在版本间有差异，
只测一个版本容易漏"。这个理由是错的：

- 那次本地绿、CI 红的根因是**本地 Node 24 而 CI 跑 22**，即"两边版本不一致"，
  不是"版本覆盖不够"。多测一个版本只是让不一致暴露出来，并没有解决问题
- 正确做法是**让 CI 与本地开发用同一个版本**，这样本地跑过的东西 CI 就一定同样表现，
  不会出现纯版本差异造成的噪音
- 双矩阵还带来实际成本：每个 PR 要等两条腿、必需检查要配两个 context、
  日志要看两遍，而这个仓库的测试只用 Node 内置能力（`node:test` / `node:assert`），
  没有任何跨版本兼容风险需要覆盖

改成单版本 **Node 24**（与本机 `v24.13.0` 一致，且 24 已是 LTS）。

## 改动清单

- `.github/workflows/ci.yml`
  - 删掉 `strategy.matrix`，`node-version` 固定 `'24'`
  - job 显示名从 `test (node ${{ matrix.node }})` 回到 **`test`**
  - 在 `node-version` 上写注释说明为什么是单版本、以及为什么必须与本地一致
- **GitHub 分支保护同步改动**（关键，见下）

## ⚠️ 必需检查的 context 名变了，必须同步改分支保护

矩阵会让检查名带上版本后缀。改成单版本后：

| | 之前 | 现在 |
| --- | --- | --- |
| 检查 context | `test (node 22)`、`test (node 24)` | `test` |

`master` 的分支保护里 `required_status_checks.contexts` 记的是**名字**。
如果不跟着改，之后每个 PR 都会永远等不到那两个旧 context 上报状态，
**在"必需检查未满足"上卡死，谁都合并不了**（`enforce_admins=true`，管理员也一样）。

所以执行顺序是：

1. 先把 `required_status_checks.contexts` **临时清空**
   （这是唯一一个 master 没有必需检查的窗口，只持续这一个 PR 的合并过程）
2. 推送本变更、开 PR，等新的 `test` 检查跑绿
3. 合并
4. 立刻把 `contexts` 设回 `["test"]`，并回读确认

命令：

```bash
# 1. 临时清空
gh api -X PUT repos/makewheels/shiftcheck-wechat-mini-program/branches/master/protection \
  -H 'Accept: application/vnd.github+json' --input - <<'JSON'
{"required_status_checks":{"strict":false,"contexts":[]},
 "enforce_admins":true,
 "required_pull_request_reviews":{"required_approving_review_count":0},
 "restrictions":null}
JSON

# 4. 设回新名字
gh api -X PUT repos/makewheels/shiftcheck-wechat-mini-program/branches/master/protection \
  -H 'Accept: application/vnd.github+json' --input - <<'JSON'
{"required_status_checks":{"strict":false,"contexts":["test"]},
 "enforce_admins":true,
 "required_pull_request_reviews":{"required_approving_review_count":0},
 "restrictions":null}
JSON
```

**以后改 job 名或加减矩阵，都要记得同步这一步。**

## 验证方式

- YAML 解析校验通过；`jobs.test.name == "test"`、`node-version == '24'`、无 `strategy` 段
- 本地 Node `v24.13.0` 跑 `node --test test/*.test.js`：106 项通过 —— 与 CI 同版本，
  所以本地结果就是 CI 结果
- 本 PR 自己的 CI 运行即以新配置（单版本、检查名 `test`）的首次实跑，绿了才合并
- 合并后回读分支保护：`contexts == ["test"]`、`strict == false`、`enforce_admins == true`、
  必需 review 数 `0`、禁 force push、禁删除，全部符合预期
- 上一个变更留下的测试写法约束仍然有效且已写进 `AGENTS.md`：
  **不要用 `t.test()` 子测试**（同步父测试里的子测试在部分 Node 版本会被取消）。
  这条与"跑几个版本"无关，是为了测试写法本身跨版本稳定

## 待确认项

- 如果日后确实需要验证多 Node 版本（例如用了较新语法），再加矩阵，
  并且**同时**更新分支保护里的 context 名

## 回滚方式

- revert 本提交恢复双矩阵；**并且必须把分支保护的 contexts 改回
  `["test (node 22)", "test (node 24)"]`**，否则同样会卡死合并
