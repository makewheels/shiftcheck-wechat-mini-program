# 2026-09-21 14:15 修活转发：utils/share.js + 11 个页面接入

## 背景 / 目的

`doc/TODO.md` 第 6 节记的遗留：11 个页面都在 `onLoad` 里调了 `wx.showShareMenu()`，
但**0 个页面实现 `onShareAppMessage`** —— 按微信规则，右上角菜单的「转发」按钮
只有页面定义了 `onShareAppMessage` 才是可点的，所以转发功能实际上一直是死的。
「分享到朋友圈」（仅 Android 客户端）则还要求页面实现 `onShareTimeline`。

## 改动清单

- 新增 `utils/share.js`：
  - `TITLES`：11 个页面的转发卡片标题（首页直接「查班神器」，其余是「查班神器：<页面标题>」，
    与各页 json 的 `navigationBarTitleText` 一一对应）
  - `appMessage()` / `timeline()`：标题取当前页面、`path` 直达当前页
    （倒班页不需要参数，好友点卡片即达同一个倒班页；页面栈为空时兜底回首页）
  - `setup(wx)`：替代原来的裸 `wx.showShareMenu()`，传
    `menus: ['shareAppMessage', 'shareTimeline']` 同时打开「转发」与「分享到朋友圈」
    （menus 需基础库 2.11.3+，更低版本被忽略、不影响「转发」本身；
    wx 由调用方传入 —— 公共模块不闭包全局，和 `calendar.refresh(this)` 同一个道理，
    测试沙箱里只有页面 js 那层看得到 wx）
- 11 个页面各接 3 行：`require` share、`onLoad` 里 `share.setup(wx)`、
  Page 配置加 `onShareAppMessage: share.appMessage, onShareTimeline: share.timeline`
- 新增 `test/share.test.js`：接线齐全（不许再绕过 setup 直接调 `wx.showShareMenu`）、
  转发标题与页面标题一一对应（含反向：TITLES 不许残留已删页面的 key）、
  appMessage/timeline 的标题与路径、空页面栈与未知路径的兜底
- `AGENTS.md`：测试文件清单八个→九个（加 `share`）、「改页面时」新增转发接法、
  目录加 `utils/share.js`
- `doc/README.md`：测试文件清单同步（原「六个」早已过期，本次照实列全九个）
- `doc/TODO.md` 勾掉对应条目
