# 2026-09-14 14:48 建立 doc/releases/：发布说明以仓库文件为唯一事实源

## 背景 / 目的

作者指出：`doc/changes/` 每次变更都有一份记录，**发布反而没有** —— v2.4.0 那份 4000 多字的
发布说明只存在于 GitHub Release 的正文里，仓库中没有对应文件。

这个不对称有实际代价：

- **进不了 PR 评审**：发布说明是对外口径，本该和代码一起被 review，写在网页上就绕过了整个流程
- **不能 diff**：改了哪句、什么时候改的，全无痕
- **会丢**：Release 一旦被删（本次就删过 v2.5.0），正文随之消失，没有任何副本
- **两边会漂**：网页上改一次，仓库里的认知就过期一次

所以确立方向：**`doc/releases/<version>.md` 是唯一事实源，GitHub Release 是它的投影**，
用 `gh release create/edit --notes-file` 单向同步过去，不在网页上写。

## 验证方式

1. **全量测试**：`node --test test/*.test.js` → **`tests 139 / pass 139 / fail 0`**（改前 137 项，新增 2 条门禁）
2. **回填脚本自带门禁预扫**：写文件前先拿 `hygiene.test.js` 的 6 条正则扫全部 13 份 Release 正文
   （32 位十六进制、疑似凭据、明文口令、雇主/环境、工具署名、冲突标记）+ 行数上限，
   结果 `✓ 没有撞到 hygiene 门禁的内容`。这一步是必要的：历史 Release 正文是别人写的，
   直接落盘可能把违规内容带进仓库
3. **链接方向**：`2.4.0.md` 里 `/master/` 出现 0 次；12 份回填文件里的 master 链接已按各自 tag 改写
4. **三条新门禁都做了反向验证，确认不是死测试**（每次都只改一处、验完立刻还原）：

   | 注入的违规 | 结果 |
   | --- | --- |
   | 删掉 `doc/releases/2.4.0.md` | 红：`✖ 当前版本必须有对应的发布说明 doc/releases/<version>.md` |
   | 往 `2.4.0.md` 末尾塞一个 `/blob/master/` 链接 | 红：同上一条（链接方向断言） |
   | 加一个 `doc/releases/v2.4.0.md`（多带 `v` 前缀） | 红：`✖ doc/releases/ 下的文件名一律是 <version>.md` |

   三次注入各自只让 1 条测试变红（`tests=18 pass=17 fail=1`），说明门禁定位准确、没有互相掩盖；
   全部还原后回到 `139 / 139 / 0`
5. **反向同步验证**：合并后用 `gh release edit v2.4.0 --notes-file doc/releases/2.4.0.md`
   把 GitHub 上那份覆盖成仓库里的内容，确立"文件 → Release"的方向（结果记在下方）
6. **没验的**：界面层一如既往没验（本次不含任何运行时代码改动）

## 待确认项

- **历史 12 份发布说明是逐字回填的**，包括当年写的口径（例如 2.3.x 提到的 DIY / 推送功能，
  那些页面在 2.4.0 已删除）。作为历史记录保持原样是对的，但读者可能困惑；
  要不要在 `doc/releases/README.md` 里加一句"历史说明反映当时的状态，不代表现在还有这些功能"
- **`doc/releases/README.md` 也放在这个目录里**，文件名门禁已把 `README.md` 排除。
  如果以后想加索引文件（如 `INDEX.md`），门禁的白名单要跟着改
- 发布说明文件头那段 `>` 引用块会被 `--notes-file` 一起发到 GitHub 上。
  这是有意的（Release 页面也该写着"要改请去改仓库文件"），但如果觉得碍眼可以去掉，
  去掉后就要靠人记住别在网页上改

## 回滚方式

- `git revert` 这个提交即可：新增 14 个文件 + 6 个文件改动，全是文档与测试，不含任何运行时代码
- 门禁回滚：删掉 `test/hygiene.test.js` 里新增的两条 `test(...)`，不影响其他门禁
- GitHub Release 侧：本次会用 `2.4.0.md` 覆盖 v2.4.0 的正文。若要回到覆盖前的版本，
  覆盖前的正文完整保存在 git 历史之外 —— 需要的话从本次提交之前的 Release API 响应恢复
  （`doc/releases/2.4.0.md` 就是在那份基础上增补的，差异只有今天新增的 4 处）
