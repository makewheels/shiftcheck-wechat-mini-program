# 2026-09-11 22:47 hygiene 门禁加显式豁免标记（解决规则条文的自指问题）

## 背景/目的

`hygiene.test.js` 会扫全仓库，禁止出现第三方工具署名之类的字样。但**规则条文本身有时必须
写出被禁的字样**才能说清楚——例如要写一条"提交信息里不要出现某种署名尾注"的规范，
就得把那个尾注的名字写出来。结果门禁把这条规范自己判成违规：

```
✖ 公开仓库里不许出现雇主/开发环境信息与第三方工具署名
  + [ 'AGENTS.md:55  6. 提交信息只描述程序改动。**不要**出现：第三方工具/模型署名（`Co-…` 之类）、' ]
```

这是自指问题，不是误报：**扫描器没法区分"在教别人别写"和"真的写了"**。

放宽正则（比如只匹配带邮箱的完整尾注格式）能绕过这一例，但会同时放过真实违规的其他形态，
等于把门禁削弱。所以改成**显式豁免**：需要豁免的行自己打标，豁免是可见、可 grep、可评审的。

## 改动清单

- `test/hygiene.test.js`
  - `hitsIn()` 跳过含 `hygiene-allow-line` 的行，并写注释说明这个标记的用途与边界
  - 新增一条守卫测试：**豁免标记不许出现在代码文件里**（`codeHits` 命中即失败），
    且只允许出现在 `AGENTS.md` / `README.md` / `doc/` 下。
    这样"用标记让代码蒙混过关"这条路是堵死的——标记只能给文档里的规则条文用
- 只改测试文件，不动产品代码

标记写法（Markdown 注释，渲染后不可见）：

```markdown
6. 提交信息里不要出现某种署名尾注（`Co-Authored-By` 之类）、<!-- hygiene-allow-line -->
```

## 验证方式

- `node --test test/*.test.js`：**107 项全部通过**（比之前多 1 项，即新增的守卫测试）
- **守卫测试的正反用例都做了变异实测**：
  - 把 `hygiene-allow-line` 塞进 `pages/index/index.js` → 守卫测试变红
    （"代码文件里出现豁免标记 = 有人在掩盖真实违规"）
  - 在 `doc/TODO.md` 里写一句第三方署名尾注、**不加**标记 → 署名门禁变红
    （说明豁免没有把正常检查一起放掉）
  - 两次变异跑完都 `git checkout` 还原，最终 107 项全绿
- **变异测试当场抓到守卫的第一版是死测试**：`hitsIn()` 会跳过带标记的行，
  于是"查找标记有没有被滥用"这个检查把自己要找的行也跳过了，塞进代码文件也照样全绿。
  修法是给 `hitsIn()` 加第三个参数 `includeMarkedLines`，检查标记本身时传 `true`。
  这条教训写进了函数注释：**任何"扫描禁用词"的检查，都不能用它自己要跳过的那套过滤逻辑去自查**
- 自指问题确已解决：下一个变更会新增 `AGENTS.md`，其中那条署名规范带标记，
  门禁不再拦它，同时**其它任何文件**里出现同样字样仍然会被拦

## 待确认项

- 豁免是行级的，一行里只要出现标记，该行所有禁用词都不再检查。
  目前只有一处用到，风险可控；如果以后豁免变多，可以改成"标记里写明豁免哪条规则"
- 是否需要在 `AGENTS.md` 里写明这个机制（下一个变更会写）

## 回滚方式

- revert 本提交；届时带标记的那一行会重新被门禁拦下，需要改成不含被禁字样的措辞
