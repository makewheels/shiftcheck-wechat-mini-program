# 2026-09-11 22:23 把 CI 设为 master 分支保护的必需检查（门禁生效）

## 背景/目的

上两个变更把测试沉淀进 `test/` 并加了 GitHub Actions，但那时 CI 只是"在 PR 上显示红绿"，
**并不拦住合并** —— 红了一样能合进 master。设成必需检查才算真正的门禁。

## 改动清单

GitHub 仓库设置（无文件改动，本记录即凭证）：

- `master` 分支保护新增 `required_status_checks`：
  - `contexts`: `["test (node 22)", "test (node 24)"]`（矩阵让检查名带上了 Node 版本，两个都要过）
  - `strict`: **false** —— 不强制"分支必须先同步 master 才能合并"。
    每个 PR 都是从当时的 master 开出来的、并且按顺序合并，不会有过期基线；
    开 strict 只会在多人并行时增加反复 rebase 的摩擦
- 其余保护项**保持不变**：`enforce_admins=true`（管理员也必须走 PR）、
  必需 review 数 `0`（即强制走 PR 机制但允许自合）、禁 force push、禁删除分支

执行的命令：

```bash
gh api -X PUT repos/makewheels/shiftcheck-wechat-mini-program/branches/master/protection \
  -H 'Accept: application/vnd.github+json' --input - <<'JSON'
{
  "required_status_checks": {
    "strict": false,
    "contexts": ["test (node 22)", "test (node 24)"]
  },
  "enforce_admins": true,
  "required_pull_request_reviews": { "required_approving_review_count": 0 },
  "restrictions": null
}
JSON
```

## 为什么等到现在才设

`master` 的保护是 `enforce_admins=true`，**先把一个还没验证过的检查设成必需，
一旦 workflow 本身写错，连管理员都合并不了任何东西**（包括修 workflow 的那个 PR）。
所以顺序是：

1. 先加 workflow，在 PR 上实跑 → 第一次就红了（Node 22 的 `t.test()` 子测试被取消）
2. 修掉测试的版本兼容问题，单独一个 PR 合并
3. 重做 workflow（22 + 24 双矩阵），PR 上两条腿都跑绿后合并
4. 确认 master 推送触发的运行也是 success
5. **才**把两个 context 设为必需检查（本次）

## 验证方式

- `gh api repos/makewheels/shiftcheck-wechat-mini-program/branches/master/protection`
  返回 `required_status_checks.contexts = ["test (node 22)", "test (node 24)"]`、`strict=false`，
  且 `enforce_admins.enabled=true`、`required_approving_review_count=0`、
  `allow_force_pushes.enabled=false`、`allow_deletions.enabled=false` 均未变
- 设置完成后 master 上已有的 CI 运行是 success，所以不会出现"设完就把自己锁在外面"的情况

## ⚠️ 万一被锁住怎么解（务必留着）

如果哪天 CI 坏了、导致任何 PR 都合并不了（`enforce_admins=true` 下管理员也合不了），两条路：

1. **修好再合**：往 PR 分支推修复，CI 会重跑，绿了就能合（推荐，大多数情况都是这条）
2. **临时摘掉必需检查**：
   ```bash
   gh api -X PUT repos/makewheels/shiftcheck-wechat-mini-program/branches/master/protection \
     -H 'Accept: application/vnd.github+json' --input - <<'JSON'
   {
     "required_status_checks": { "strict": false, "contexts": [] },
     "enforce_admins": true,
     "required_pull_request_reviews": { "required_approving_review_count": 0 },
     "restrictions": null
   }
   JSON
   ```
   合完修复后**记得把两个 context 加回来**，否则门禁就名存实亡了

## 回滚方式

- 用上面第 2 条命令把 `contexts` 清空即可；CI 仍会在 PR 上跑，只是不再拦合并
