# 2026-09-14 15:55 README 去掉内联「版本更新日志」，事实源收敛到 doc/releases/

## 背景 / 目的

用户指出：changelog 已经有独立文件了（`doc/releases/` 按版本、`doc/changes/` 按改动），
根目录 README 里再内联一份「版本更新日志」是重复的，要求改 README。

重复的真实代价这个仓库已经付过一次：2.4.0 先打了 tag、之后又合了 6 个修复，
结果 **README 的更新日志比 tag 少 7 条**，只能回头补一个 PR 并强制移动 tag
（见 `doc/changes/2026-09-12-000740-release-notes-240.md`）。两处维护必然漂移。

**版本归属**：本次改动属于 **2.5.0 线**，但用户明确「先不建立版本号，我说要发版再建立」。
所以本次**不 bump `appVersion`、不新建 `doc/releases/2.5.0.md`、不建 tag、不建 Release**，
只是把文档结构理顺。门禁保证了这一点不会意外发生（见下）。

## 改动清单

- **`README.md`**：删除内联的「版本更新日志」整节（2.3.0 ~ 2.4.0 共 6 个版本条目、约 40 行），
  换成一张指针表格：按版本看 `doc/releases/<版本>.md`、按改动看 `doc/changes/`，
  并注明当前版本以 `app.js` 的 `appVersion` 为准。README 从 60 行降到 21 行
- **`test/hygiene.test.js`**：
  - 原「appVersion 与 README 更新日志里最新版本一致」改为
    「**appVersion 等于 `doc/releases/` 里最新的版本**」。这条门禁双向咬合：
    bump 了 appVersion 就必须有同版本发布说明文件；新建了发布说明文件就必须 bump appVersion ——
    必须同一次改动完成。**还没到发版时两者都不动，门禁自然绿**（这正是本次"不建版本号"能安全落地的原因）
  - 新增门禁「**README 里不许再内联版本更新日志**」：README 出现 `## <版本号>` 标题就红，
    防止有人把日志又抄回 README
- **`doc/releases/2.3.0.md` ~ `2.3.4.md`**：这 5 份里的「README 更新日志原文」小节标题
  与补录脚注改措辞，注明「README 该节已于 2026-09-14 移除，原文保留在此」——
  否则脚注指向一个已经不存在的小节，又是漂移
- **流程文档同步**（3 处）：`doc/发布前检查单.md` 第 8 节第 1、2 步、
  `doc/README.md`「发版」一节、`doc/releases/README.md` 分工说明 ——
  都改成"README 不写更新日志、发布说明是唯一对外口径、appVersion 与发布说明同一次改动"

**不改任何运行时代码、不改 `appVersion`、不新建版本文件。**
