# 2026-09-11 22:13 测试改成扁平顶层 test()，修 Node 22 上子测试被取消的问题

## 背景/目的

加 CI 门禁时，workflow 第一次实跑（Node 22）就红了一片：

```
not ok 2 - 五班三倒-总览
  error: 'test did not finish before its parent and was cancelled'
...
not ok 31 - 锚点守卫：getTotalDays() 在锚点当天为 0、后一天 +1、前一天 -1
  error: '8 subtests failed'
```

原因是 `test/shift-pages.test.js` 里用了「同步父测试 + `t.test()` 子测试」的写法：

```js
test('锚点守卫：…', function (t) {
  pg.PAGES.forEach(function (meta) {
    t.test(meta.name, function () { … })   // 返回 Promise，没人 await
  })
})                                          // 父函数同步返回 -> 子测试被判定为"没跑完"
```

`t.test()` 返回 Promise，父测试函数同步返回时子测试还没结束。**Node 22 会取消它们并报失败，
Node 24 不会** —— 本地是 Node 24，所以这个问题在本地完全看不出来，只有 CI 才暴露。

## 改动清单

- `test/shift-pages.test.js`：把 6 组「父测试 + 循环里的 `t.test()` 子测试」全部展开成**顶层 `test()`**，
  在模块加载时用 `forEach` 按「页面 × 班组」逐个注册。每个测试的名字带上页面与班组
  （如 `周期性 班次(d)===班次(d+N)：五班三倒-个人 3班`），失败时定位能力不变
- 金标准快照那一项原本是「每个 key 一个子测试」，改成一次比对、把所有不一致收集起来一次性报出
  （附带现在值与基线值，比逐个红更好读）
- 文件头注释写明**为什么刻意不用 `t.test()`**，避免以后有人"顺手改回更漂亮的嵌套写法"
- 只改测试文件，**没有动任何产品代码，也没有改断言内容**

## 验证方式

- 本地 Node 24：`node --test test/*.test.js` **106 项全部通过，98 ms**
  （顶层测试数从 132 降到 106，是因为原来的子测试合并成了顶层测试；断言条数没有减少）
- 结构上不再依赖 node:test 的父子测试行为，因此跨 Node 版本表现一致
- **Node 22 上的最终确认由下一个 PR 的 CI 完成**（workflow 会跑 22 + 24 双矩阵）。
  本 PR 合并时仓库里还没有 CI，所以这一步是"先按原理修，紧接着用 CI 实证"
