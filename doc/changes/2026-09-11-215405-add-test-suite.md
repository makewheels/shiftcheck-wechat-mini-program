# 2026-09-11 21:54 建立测试套件（node:test，零依赖）与代码卫生门禁

## 背景/目的

仓库原来没有任何自动化测试，所有校验都是临时脚本跑完就扔。倒班这种东西错一个常量就整页错班、
而且肉眼看不出来；隐私和废弃 API 的坑也是修完就可能被人加回来。所以把校验沉淀成仓库里的测试，
让"改坏了"这件事在本地和 CI 里立刻变红。

## 改动清单

**新增 `test/`（Node 内置 `node:test` + `node:assert`，零第三方依赖，不建 `package.json`）**

- `test/helpers/miniprogram.js`：小程序运行环境替身。用假的 `Page()` / `Component()` / `App()` / `wx` /
  `getApp()` / LeanCloud SDK 沙箱加载页面 js，返回可直接调方法的实例（`setData` 只合并进 `data`，不渲染）。
  因此测试**不启动模拟器**，也能在 GitHub Actions 的 Linux runner 上跑（微信开发者工具没有 Linux 版）
- `test/helpers/pages.js`：9 个倒班页的清单（锚点日期、循环长度、类型）与 diy 页用的假规则数据
- `test/shift.test.js`：`mod()` 负数行为、有符号 `daysBetween()`、`dateKey` 补零与反解、`weekName`、闰年
- `test/holiday.test.js`：逐日扫描两年数据 —— 放假日 28/33 天、补班日 5/6 天与国务院通知一致；
  补班日必须落在周末；标注必带名称；36 个官方日期抽查；未内置年份（2024/2027/2030）必须返回空、不许编造
- `test/calendar.test.js`：网格几何（每行 7 格、格子数等于当月天数、周一起始的前置空格、闰年 2 月）、
  今天标记、节假日标注、`work` 三态（true/false/null）、`refresh` 在列表模式下不建数据、
  `changeMonth` 月末收敛（1/31→2/28、闰年→2/29）与跨年、`dayTap` 回列表、空 detail 不改状态、
  `onDate` 正常与抛错两条路径都要还原日期
- `test/shift-pages.test.js`：**最要紧的一份**，五条互相独立的约束
  1. 锚点守卫 —— 各页 `getTotalDays()` 在锚点当天为 0、后一天 +1、前一天 **-1**
  2. 周期性不变量 —— `班次(d) === 班次(d + N)`，锚点前后各 60 天 × 全部班组
  3. 经警队实测班表 —— 12 个与真实排班核对过的日期逐日断言；锚点前后各 200 天每天恰好 1 个班上班、
     总览页与个人页一致；一班 7 天列表为「上1休3」
  4. 金标准快照 —— `test/fixtures/golden-rows.json` 锁定 21 组已校准输出（9 页 × 全部班组，2026-09-11 起 7 天），
     班组循环表被误改立刻红；`GOLDEN_UPDATE=1` 才重写
  5. 列表 == 日历 —— 9 页 × 全部班组 × 4 个月份，日历每格文字必须等于列表模式同一天的文字
     （保证日历没有第二套班次算法），节假日标注与 `utils/holiday.js` 一致
- `test/structure.test.js`：`app.json` 注册页面的 js/json/wxml 齐全且非空；磁盘上的页面目录都已注册（不留死页面）；
  所有 `navigateTo`/`redirectTo`/`reLaunch`/`switchTab` 目标都已注册；`usingComponents` 路径可解析且组件 json
  带 `"component": true`；wxml 里 `bind*`/`catch*` 绑定的处理函数在对应 js 中存在；
  `project.config.json` 的 appid 不是游客 appid；全部 json 可解析
- `test/hygiene.test.js`：把踩过的坑变成门禁 ——
  页面里不许出现 `AV.User.current().toJSON()`；`app.js` 必须有 `getOpenid`/`withOpenid`/`loginFailTip`/
  `initUpdateManager`/`login`，升级三个回调都要注册且 **`onUpdateReady` 不能嵌在 `onCheckForUpdate` 回调里**
  （用括号配平判断，逐处检查）；不许 `Math.abs(date2-date1)` 与裸 `total % N`；
  不许 `wx.getSystemInfoSync` / `wx.getUserInfo` / `wx.getUserProfile` / `open-type="getUserInfo"`；
  剪贴板只允许出现在 `importRuleByKey`，位置类隐私接口一个都不许有；
  代码里不许出现 ip138，任何文件不许出现明文凭据（带 token 的 URL、32 位十六进制、`ghp_`/`AKIA`/`sk-`、明文口令）；
  mta 与 authUserInfo 死代码不许复活；不许有合并冲突标记；
  公开仓库里不许出现雇主/企业网络环境信息与第三方工具署名；
  `app.js` 的 `appVersion` 必须与 README 更新日志里最新版本号一致；
  变更记录文件名必须符合 `YYYY-MM-DD-HHMMSS-简短说明.md`（规范调整前的旧格式记录放行）

**文档**

- `doc/README.md` 新增「测试」小节：怎么跑、六个文件各管什么、金标准什么时候才该更新、

## 待确认项

- 金标准快照锁的是"当前已校准的行为"，它证明的是**没有意外变化**，不是"班表绝对正确"；
  班表的正确性由第 3 条（与真实排班核对过的经警队班表）和周期性不变量保证
- `test/` 不会被打包上传（`project.config.json` 的 `ignoreUploadUnusedFiles: true`），
  但如果日后要更保险，可以在 `packOptions.ignore` 里显式排除 `test/` 与 `.github/`
- 界面层（渲染、换行、点击手感）测不了：微信开发者工具没有 Linux 版，
  本机 CLI 服务端口也是关闭的。要做真机/模拟器级 E2E，需要开启服务端口并引入 `miniprogram-automator`
