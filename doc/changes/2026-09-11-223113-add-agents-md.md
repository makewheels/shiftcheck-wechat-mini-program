# 2026-09-11 22:31 新增 AGENTS.md（给 AI agent / 新协作者的仓库须知）

## 背景/目的

`doc/README.md` 写的是**流程规范**（走 PR、留变更记录），但没有写"这个仓库里哪些地方一改就坏、
坏了还看不出来"。这几天踩的坑（锚点日期、`Math.abs()` 取天数差、`AV.User.current()` 为 null、
`scope.userInfo` 已失效、隐私接口、node:test 的版本差异）都散落在各份变更记录里，
新来的人（或新来的 agent）不会逐份读完。集中写一份须知，把"别这么干"放在最显眼的地方。

## 改动清单

新增 `AGENTS.md`，内容：

- **这是什么项目**：原生小程序、无框架无构建无 npm 依赖、LeanCloud 后端、appid
- **跑测试**：`node --test test/*.test.js`（并写明给目录会在部分 Node 版本上报错）、
  零依赖所以不要建 `package.json`、六个测试文件各管什么、金标准快照什么时候才该更新、
  **写测试不要用 `t.test()` 子测试**（Node 22 会取消未结束的子测试，本地绿 CI 红）
- **CI 门禁**：单版本 Node 24（与本地一致）、必需检查名 `test`、改 job 名或加减矩阵必须同步改
  分支保护里的 context 名（否则 PR 会卡死）、被挡住时该推修复而不是摘检查、摘检查的命令在哪、
  CI 跑不了模拟器所以界面层永远要人工过
- **硬约定**：分支 + PR、分支名不带斜杠、变更记录命名带时分秒、一次 PR 只做一件事、
  多 PR 按"合一个再开下一个"推进、提交信息里不许出现第三方工具署名与雇主/开发环境信息
- **改排班逻辑前必读**：锚点是实测校准数据、天数差与取模必须走 `utils/shift.js`、
  班组循环表不要"顺手优化"、校验排班改动的正确姿势（改动前后逐日比对 + 两条不变量）
- **改页面时**：取 openid 只能用 `app.getOpenid()` / `app.withOpenid()`、查询结果取 `[0]` 前判空、
  新增倒班页接月日历的固定步骤、自定义组件样式隔离、结构测试会校验哪些对应关系
- **节假日数据**：每年 11 月要手工补、**不要凭记忆或让模型推算日期**
  （曾两次收到编造的下一年数据 + 伪造的 gov.cn 链接，靠"通知发布日期在未来"才识破）
- **隐私与合规**：不要加回静默采集、现存唯一隐私接口在哪、不要硬编码 token、
  已废弃 API 清单与替代写法
- **本机验证的边界**：开发者工具 CLI 服务端口默认关闭，所以命令行编译/预览/上传/自动化都用不了；
  交付时必须说清哪些没验过
- **目录说明**

同时在 `README.md` 顶部加一行指向 `AGENTS.md`，让它能被发现。
