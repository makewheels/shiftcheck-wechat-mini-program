# 2026-09-14 12:13 发布准备 2.4.0：收回 2.5.0 版本标识、修 Windows 下跑红与空跑的测试、新增单文件行数门禁

## 背景 / 目的

三件事，都是为了让 2.4.0 能真正发出去。

### 1. 收回 2.5.0，本次发版定为 2.4.0

上一轮把 `app.js` 的版本号推到 `2.5.0`，并打了 tag、建了 GitHub Release，但这次发版并没有得到确认。
**代码内容不动**：master 现状（删除 DIY 与推送两条链路、注册页面 20 → 11、月日历、一批发布前修复）
就是本次要发的东西，只把版本标识从 2.5.0 收回 2.4.0，README 里 `## 2.5.0` 那一段并入 `## 2.4.0`。

tag 与 Release 的处理（在仓库外，不在本 PR 里）：

- `v2.5.0` 的 tag 与 Release 删除
- `v2.4.0` 的 tag 从 `b6259b8` 移到本次合并后的提交，Release 说明补上删除两条链路的部分
- 历史 `v2.0.0` ~ `v2.3.4` 的 12 个 Release 保留

### 2. 测试套件在 Windows 上跑红，还有一条门禁静默空跑

测试是在 macOS 上写的，路径判断用了 `'/libs/'`、`'/test/'`、`'/pages/'` 这类正斜杠字面量。
Windows 上 `path.join` / `path.relative` 返回反斜杠，这些判断一个都匹配不上，后果分三档：

| 文件 | 后果 |
| --- | --- |
| `test/structure.test.js` 「代码里所有跳转目标都在 app.json 注册」 | **跑红**：`path.posix.dirname('pages\index\index.js')` 得到 `.`，相对跳转算不出来，10 个跳转目标全部误报未注册 |
| `test/structure.test.js` 「磁盘上的页面目录都在 app.json 注册」 | **静默空跑**：`f.includes('/pages/')` 恒为 false → `dirs` 恒为空 → `unregistered` 恒为空 → 永远绿。这条门禁在 Windows 上等于不存在 |
| `test/hygiene.test.js` 扫描范围 | `libs/` 与 `test/` 的排除失效，第三方 SDK 与测试文件都被算进业务代码扫描范围；`hygiene-allow-line` 豁免标记的归属判断（`startsWith('doc/')`）同样跑红 |

CI 跑在 Linux 上，这三档差别在 CI 里全都看不出来，所以「CI 绿」并不代表本机能验。

**必须先修这个**：否则下面第 3 条新增的行数门禁，在 Windows 上会把 1246 行的
`libs/leancloud-adapters-weapp.js` 算进来而必红，CI 却绿 —— 正是 AGENTS.md 里说的
「本地绿、CI 红」那类纯环境噪音的反向版本。

### 3. 补一条体量门禁：单文件最多 500 行

原先的门禁管住了「不许写什么」（废弃 API、隐私接口、明文凭据、死代码复活），
没有任何一条管「一个文件能长到多大」。8 个倒班页高度雷同，
缺这条红线时最容易发生的就是一页一页往里堆。

## 验证方式

本机 Node `v24.15.0`（与 CI 的 Node 24 一致）。

1. **全量测试**：`node --test test/*.test.js` → `tests 131 / pass 131 / fail 0`
   （改前同一台机器上是 2 项红）
2. **反向验证 A —— 新门禁不是死测试**：把 `MAX_FILE_LINES` 临时改成 300 再跑
   `node --test test/hygiene.test.js`，退出码非 0，报错准确列出 4 个超标文件：
   `pages/wbsd/worker/worker.js（352 行）`、`pages/sbbd/worker/worker.js（331 行）`、
   `pages/wbsd/director/director.js（309 行）`、`pages/sbsd/worker/worker.js（308 行）`。
   路径是正斜杠，说明归一化生效。改回 500 后恢复绿
3. **反向验证 B —— 原先空跑的那条现在真的在跑**：从 `app.json` 摘掉
   `pages/jjd/director/director` 再跑 `node --test test/structure.test.js`，退出码非 0，
   报「跳转目标未注册：pages/index/index.js -> pages/jjd/director/director」。还原后恢复绿
4. **残留引用**：`git grep -n "2\.5\.0" -- . ':(exclude)libs'` → 无命中
5. **改动面**：`git diff --stat` → 9 个文件 `+86 / -33`，无整文件行尾改写
6. **没验的**：界面层（渲染、换行、点击手感）一如既往测不了，需要在开发者工具或真机上看；
   「上传 → 检测到新版本 → 弹窗 → 重启」的强制升级全链路仍未跑通（`doc/TODO.md` 第 3 节）

## 回滚方式

- 本 PR 的改动：`git revert` 这个合并提交，或 revert 组成它的三个提交
- 版本号：单独把 `app.js` 的 `appVersion` 改回 `2.5.0` 即可，
  `test/hygiene.test.js` 有一条断言守着它与 README 最新版本号一致，两边不同步会红
- 行数门禁：删掉 `test/hygiene.test.js` 里「文件体量」小节（常量 + 一条测试），不影响其他门禁
- 路径归一化：`relOf()` 在 Linux 上是恒等变换（`mp.rel` 本来就不含反斜杠），
  所以这三处改动对 CI 行为没有任何影响，回滚只需还原两个测试文件
- 仓库外的 tag / Release：`v2.5.0` 删除后若要恢复，需要重新指向 `874ae7d`；
  `v2.4.0` 移动前的原始位置是 `b6259b8`
