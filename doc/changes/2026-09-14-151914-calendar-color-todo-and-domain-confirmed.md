## RDAP 查到的事实（2026-09-14）

```
handle      : （无）
ldhName     : shiftcheck.work
status      : client transfer prohibited, pending delete, redemption period
registration: 2025-08-09T05:28:19Z
expiration  : 2026-08-09T05:28:19Z
last changed: 2026-08-09T23:05:11Z
nameservers : expire2.cnolnic.com, expire1.cnolnic.com
```

解读：域名 2026-08-09 到期未续费，现在处于**赎回期 / 待删除**，
权威 NS 已被注册商换成过期停放服务器。所以 `api.leancloud.mp.shiftcheck.work`
对全球所有用户都解析不到 —— 之前观察到的 `getaddrinfo failed`、代理 CONNECT 返回 `502`、
模拟器里 `POST /1.1/users` 报 `net::ERR_TUNNEL_CONNECTION_FAILED`，全部由此解释。

**为什么之前只能"疑似"**：本机网络按类别封了 DoH 服务（`dns.google` / `cloudflare-dns.com`
都返回拦截页），所以没法用公共递归验证全球解析状态。RDAP 走的是注册数据协议、
不在被封的类别里，一次查询就给出了权威答案。这个路子值得记住。

**赎回期有时限**，过期域名就彻底没了 —— 这是"下一版要决定"里唯一带时间压力的一项。

## 界面级自动化验证（本次搭起来的能力，记进文档备查）

仓库原来认为界面层无法自动验证。本次实测打通了一条路，脚本与依赖都在 `%TEMP%` 下、
**不进仓库**（仓库是零依赖的，加 `package.json` 会让开发者工具的「构建 npm」介入）：

```bash
# 1. 开自动化端口（IDE 服务端口需已开启）
cli.bat auto --project <仓库路径> --auto-port 9420

# 2. 在装了 miniprogram-automator 的目录里连上去
node inspect.js        # 脚本见 %TEMP%\wxauto\inspect.js
```

实测能做到的事：

- **11 个页面逐个 `reLaunch` 并断言加载成功**（本次 11/11）
- **读 `page.data()` 验证业务数据**：8 个倒班页列表 7/7 行有内容；
  `toggleView` 后 `viewMode` 变 `calendar`、`cal.title` 从 `2026年9月` 翻到 `2026年10月`
- **`callMethod()` 直接调页面方法**（`toggleView` / `nextMonth` / `backMonth`），不用找按钮选择器
- **`screenshot({path})` 逐页截图**，人工看图确认渲染（本次确认了月日历的节假日角标、
  今天高亮、上/休底色都正确）
- **`on('console')` / `on('exception')` 抓 JS 层 console 与未捕获异常**（本次两者都是 0 条）

**一个明确的边界**：`on('console')` 走的是 `App.logAdded` 通道，只收 JS 的 `console.*` 调用；
**网络层的 `net::ERR_*` 收不到**（那是渲染进程 Chromium 网络栈的消息，不经过小程序日志协议）。
所以"console 里没有报错"不等于"没有网络错误"，网络错误仍要靠独立探测
（TCP/CONNECT 探针、RDAP 这类）来确认。本次两者都做了，结论互相印证。
